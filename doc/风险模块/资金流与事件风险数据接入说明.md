# 资金流与事件风险数据接入说明

## 定位

本模块只提供风险指标的规范化输入、事件事实、来源质量和覆盖报告，不计算最终风险分，也不输出确定性投资结论。所有结果均用于辅助决策。

## 数据集与指标映射

| 数据集 | 首选 AKShare / AKTools 端点 | 风险输入 | 处理约束 |
|---|---|---|---|
| `margin_financing` | `stock_margin_account_info` | `V5` 杠杆存量、`A1` 实际去化代理 | 保留余额水平和变化，不在采集层计算最终风险分 |
| `etf_fund_flow` | 衍生网关 `/api/risk/etf-redemption`；未配置时仅以 `fund_etf_spot_em()` 降级 | `A2` 基金 / ETF 申赎资金流 | 原生现货表是当前二级市场订单流代理，不是申赎事实；五年正式评分必须使用衍生网关完整序列 |
| `earnings_forecast` | `stock_yjyg_em` | `T1` 现金流 | 按报告期调用；公开历史可追溯至较早年份，但仍以覆盖报告为准 |
| `stock_announcement` | `stock_zh_a_disclosure_report_cninfo` | `T1` 现金流、`T2` 折现率代理、`T3` 融资条件、`T4` 市场信任 | 只有进入受控经济含义字典的公告才生成风险事件 |
| `share_unlock` | `stock_restricted_release_queue_sina` | `M` 窗口候选 | 计划解禁不单独提高维度分；`stock_restricted_release_summary_em` 仅适合作近期补充 |
| `share_reduction` | `stock_ggcg_em` | `M` 窗口候选 | 只有实际减持且资金流或价格确认时标记 `confirmed=true`；`stock_hold_management_detail_cninfo` 仅近一年 |

其中 `T1` 至 `T4` 的受控经济含义依次为 `cash_flow`、`discount_rate`、`financing_conditions`、`market_trust`。无法映射的公告返回有效零事件，不得按标题或关键词直接产生高等级事件。

## 质量、时间和补源规则

- 成功查询且没有事件为 `valid_zero`；请求、解析或上游服务失败为 `unavailable`，两者不得互换。
- 每条记录保留 `occurredAt`、`observedAt`、`availableAt`、`source`、质量状态和稳定 `eventKey`。计划事件允许 `occurredAt` 晚于 `observedAt`。
- 持久化 `eventKey` 使用 `<eventType>:sha256:<64 位十六进制>`，对完整 canonical business key 做 SHA-256，长度始终不超过 `risk_event_fact.event_key VARCHAR(128)`。未截断的 canonical business key 和原始 `sourceRecordId` 同时保存在事件 payload 中，便于审计预测指标、上市批次和股东等长字段，且不会因截断发生碰撞。
- 回填按请求的 `startDate`、`endDate` 和 `checkpoint` 执行，Provider 将断点原样传给数据源，并返回 `nextCheckpoint`。数据源应从断点之后返回记录，Provider 会额外过滤断点边界的重复游标；同一批源记录通过稳定键去重，持久化侧应继续使用 `eventKey` 幂等写入。
- 计算时只使用 `availableAt` 不晚于回填截止日的数据。即使事件已经发生，若当时尚未可得，也不得提前进入历史快照。
- 主源只有在 `unavailable` 或 `insufficient_history` 时才尝试 `FlowEventSupplementProvider`；成功零值不会触发补源。补源原因写入记录属性和覆盖报告，两源均失败仍为 `unavailable`。
- 近期接口无法覆盖五年时，覆盖报告列出最早可用日期、历史缺口、有效、零值、失败、历史不足数量及加权覆盖率，不生成合成历史。
- `RISK_WARNING_DERIVED_GATEWAY_BASE_URL` 配置规范化衍生网关。ETF 网关请求为 `/api/risk/etf-redemption?start_date=yyyyMMdd&end_date=yyyyMMdd&objects=market:CN-A`，并支持可选 `cursor`。响应必须返回每条记录的 `tradeDate`、`netFlow`、`referenceAssets`、`observedAt`、`availableAt`，且 `meta.historyComplete=true`、`meta.earliestAvailableDate` 非空并且不晚于请求 `startDate`；否则整批按部分历史处理，已有记录仅供审计且不得推进 checkpoint。
- `fund_etf_spot_em()` 的记录固定标记 `proxy=true`、`proxyType=secondaryMarketOrderFlow` 和 `historyComplete=false`，事件代码为 `etf_order_flow_proxy`，不得标记成赎回事实，也不得生成正式 `A2` 风险证据或推进 checkpoint。
- `stock_restricted_release_queue_sina` 与 `stock_ggcg_em` 的数量单位为“万股”，规范化单位为 `tenThousandShares`。两者原生接口仅提供近期数据：非空响应可保存当前事件，但事件质量与 Provider 批次均降为 `insufficient_history`，记录 `sourceQuality/partialHistoryReason`，正式评分只读取 `available/valid_zero`，且不推进 checkpoint；只有明确 `historyComplete=true` 的成功空响应才是 `valid_zero`。绝对股数不能直接当作 0—1 风险强度；只有上游明确披露的流通股/总股本比例才写入 `modifierRatio`。

## 真实 AKTools 冒烟清单

下列命令仅是部署后的人工冒烟入口，本次实现没有执行真实 AKTools 端点联网验证。当前签名已对照部署锁定的 AKShare 1.18.64 官方 wheel 源码核验；不同 AKTools 镜像仍可能产生字段差异，上线前应以当前镜像 OpenAPI 为准。

```bash
curl -G 'http://127.0.0.1:8090/api/public/stock_margin_account_info'

curl -G 'http://127.0.0.1:8090/api/public/fund_etf_spot_em'

curl -G 'http://127.0.0.1:8090/api/public/stock_yjyg_em' \
  --data-urlencode 'date=20260630'

curl -G 'http://127.0.0.1:8090/api/public/stock_zh_a_disclosure_report_cninfo' \
  --data-urlencode 'symbol=600519' --data-urlencode 'start_date=20210101' \
  --data-urlencode 'end_date=20260718'

curl -G 'http://127.0.0.1:8090/api/public/stock_restricted_release_queue_sina' \
  --data-urlencode 'symbol=600519'

curl -G 'http://127.0.0.1:8090/api/public/stock_ggcg_em'

curl -G 'http://127.0.0.1:18090/api/risk/etf-redemption' \
  --data-urlencode 'start_date=20210101' --data-urlencode 'end_date=20260718' \
  --data-urlencode 'objects=market:CN-A'
```

原生适配器同时接受 AKTools 直接数组及 `data/meta` 包装，但严格遵循各函数原生参数，不会向无参函数追加统一日期或对象参数。只有衍生网关使用规范化的 `data/meta` 契约。生产凭据只能由部署环境注入，不得写入仓库。
