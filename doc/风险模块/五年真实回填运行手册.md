# 风险预警五年真实回填运行手册

## 1. 用途与边界

本手册用于执行 A 股日频风险预警五年真实回填。命令只供内部运维使用，以非 Web 进程启动，执行完即退出；不新增风险写 API，也不会随普通服务启动自动运行。

风险分是综合指标分数，只用于辅助决策，不代表暴跌概率，不构成投资建议，也不保证收益。数据覆盖不足时命令会保留审计数据并停止扩全市场，不会制造正式风险结论。

## 2. 前置条件

- JDK 21；
- Maven 3.9 或更高版本；
- MySQL 已由 Flyway 升级到 V2；
- 本地 `trade_calendar` 包含所选结束日，且该日为 A 股开市日；
- `stock_base` 中存在正常上市的活跃 A 股；
- AKTools 可访问；
- 规范化历史衍生网关可访问，并实现历史行业归属、行情、估值、宽度、跨市场和 ETF 申赎契约；
- 目标数据库已完成可恢复备份。

仅有 AKTools 当前快照不足以通过 80% 实际覆盖关卡。未配置规范化历史衍生网关时，预检会以退出码 3 停止，不会发起真实回填。

## 3. 数据库备份

不要把数据库账号或密码写入命令历史。先创建仅当前用户可读的 MySQL 客户端配置文件，并通过环境变量传入路径和数据库名：

```bash
export MYSQL_CREDENTIALS_FILE=/absolute/path/mysql-client.cnf
export RISK_DATABASE_NAME=stock_ai_rule_system
export RISK_BACKUP_FILE=/Users/zengbojia/githome/stock-ai-rule-system-db-pre-risk-backfill-20260719.sql

mysqldump --defaults-extra-file="$MYSQL_CREDENTIALS_FILE" \
  --single-transaction --set-gtid-purged=OFF \
  "$RISK_DATABASE_NAME" > "$RISK_BACKUP_FILE"
shasum -a 256 "$RISK_BACKUP_FILE"
```

记录备份文件的 SHA-256。首次样本和首次全市场执行前都要确认该文件存在且非空。

恢复演练使用独立临时库；不要直接覆盖正在使用的库：

```bash
mysql --defaults-extra-file="$MYSQL_CREDENTIALS_FILE" risk_restore_test < "$RISK_BACKUP_FILE"
```

## 4. 选择回填结束日

结束日必须显式提供，且必须在本地 A 股交易日历中为开市日：

```sql
SELECT trade_date, market, is_open
FROM trade_calendar
WHERE market IN ('CN', 'A股', 'SSE', 'SZSE', 'SH', 'SZ')
  AND is_open = 1
ORDER BY trade_date DESC
LIMIT 10;
```

评分窗口是结束日前五年，采集窗口再向前扩六年作为滚动分位基线。结束日、模型版本、分块大小和数据源地址在一次运行中不得修改。

## 6. 执行模式

### 6.1 sample：只执行样本

首次执行必须先用 `sample`。默认从活跃 A 股全序列中等距选择 50 只；也可以通过 `RISK_WARNING_BACKFILL_SYMBOLS` 传入逗号分隔的可复现样本。

```bash
cd /Users/zengbojia/githome/stock-ai-rule-system/stock-ai-rule-system-service
export RISK_WARNING_BACKFILL_MODE=sample
./scripts/risk-backfill.sh
```

样本只有同时满足以下条件才通过：

- 不可用数据集数量为 0；
- 26 项指标实际加权覆盖至少 80%；
- V、C、A 各至少 60%，且 T 或 S 至少一侧达到 60%；
- 核心行情覆盖完整五年评分窗口；
- `1-5d`、`5-20d`、`20-60d` 三个周期都有正式市场快照；
- 正式快照完整度至少 80%；
- 所有 `available_at >= observed_at`；
- 所有闸门记录均为 `enforced = 0`。

### 6.2 staged：样本通过后自动扩全市场

```bash
export RISK_WARNING_BACKFILL_MODE=staged
./scripts/risk-backfill.sh
```

`staged` 会重新执行确定性样本。样本门控失败时不会调用全市场 Provider；通过后按默认每 200 只股票分块扩展到全部活跃 A 股。

### 6.3 full：复用已有样本通过报告

```bash
export RISK_WARNING_BACKFILL_MODE=full
./scripts/risk-backfill.sh
```

`full` 不重新跑样本，但报告目录中必须已有同模型版本、同结束日且 `sampleGatePassed=true` 的 `sample` 或 `staged` 报告。缺少匹配报告时退出码为 2。

## 7. 报告和退出码

默认报告目录为 `stock-ai-rule-system-service/target/risk-backfill/reports`。报告先写临时文件，再原子移动为 `risk-backfill-*.json`。报告包含运行 ID、窗口、样本、摘要、26 项覆盖、五维覆盖、三个周期、checkpoint 和明确失败原因；敏感赋值和 URL 用户信息会被脱敏。

| 退出码 | 含义 |
|---:|---|
| 0 | 所选模式完成且验收通过 |
| 2 | 参数、开关、确认令牌或 full 前置报告错误 |
| 3 | Flyway、数据库、交易日、股票池或数据源预检失败 |
| 4 | 样本回填执行失败 |
| 5 | 样本实际覆盖门控未通过 |
| 6 | 全市场回填失败，可按断点续跑 |
| 7 | 全市场最终数据验收失败 |
| 8 | JSON 报告写入失败 |

命令非零退出后，先读取最新 JSON 报告，不要直接改表或删除 checkpoint。

## 8. 断点续跑

`risk_ingestion_checkpoint` 按 Provider、数据集和对象范围保存 cursor。成功数据使用唯一键幂等 upsert；`unavailable` 和历史不足不会把失败范围标记为成功。

断点续跑步骤：

1. 保持结束日、模型版本、分块大小、模式和数据源地址不变；
2. 查询失败 checkpoint 的 `quality_status` 与 `last_error`；
3. 修复数据源；
4. 使用相同环境变量重新执行脚本；
5. 对比执行前后表行数和 cursor，cursor 只允许前进，不允许回退。

```sql
SELECT provider_code, dataset_code, scope_key, checkpoint_at,
       quality_status, last_error
FROM risk_ingestion_checkpoint
ORDER BY quality_status, provider_code, dataset_code, scope_key;
```

## 9. 只读验收

```sql
SELECT horizon, COUNT(*) AS snapshot_count,
       SUM(completeness >= 0.80 AND risk_level IS NOT NULL) AS formal_count,
       MIN(trade_date) AS earliest_date, MAX(trade_date) AS latest_date
FROM risk_score_snapshot
WHERE model_version = 'risk-warning-v1'
GROUP BY horizon
ORDER BY horizon;

SELECT COUNT(*) AS enforced_count
FROM risk_gate_result
WHERE enforced <> 0;

SELECT
  (SELECT COUNT(*) FROM risk_indicator_observation WHERE available_at < observed_at)
  + (SELECT COUNT(*) FROM risk_event_fact WHERE available_at < observed_at)
  + (SELECT COUNT(*) FROM risk_score_snapshot WHERE available_at < observed_at)
  + (SELECT COUNT(*) FROM risk_score_evidence WHERE available_at < observed_at)
  + (SELECT COUNT(*) FROM risk_gate_result WHERE available_at < observed_at)
  AS timestamp_violation_count;
```

重复相同参数执行后，再比较 `risk_indicator_observation`、`risk_event_fact`、`risk_score_snapshot`、`risk_score_evidence` 和 `risk_gate_result` 的唯一身份行数，不能因为重跑产生重复记录。

服务启动后验证三个周期只读接口：

```text
GET /api/risks/overview?horizon=1-5d
GET /api/risks/overview?horizon=5-20d
GET /api/risks/overview?horizon=20-60d
```

接口应返回 200。风险中心应展示真实交易日和证据；覆盖不足的对象只显示“数据不足”，不得展示正式风险等级。
