# 风险中心同步与暂定评估设计

## 背景与目标

当前风险中心已经保存了部分五年风险观测和证据，但只完成了市场与样本股票回填，正式评分又要求整体覆盖率达到 80%，导致页面大量显示“数据不足”。行业暴露没有形成可用记录，进一步造成行业矩阵为空和个股三层合成缺失。

本次目标是先形成可用的数据闭环：

1. 用户可手动同步最新市场数据。
2. 用户可对选中的股票执行增量同步，并联动同步市场和所属行业。
3. 正式评分规则保持不变；数据未达正式门槛时，基于已有证据输出明确标记的暂定评估。
4. 风险中心展示实际使用和缺失的指标，不再使用笼统的“数据不足”覆盖全部信息。
5. 修复当前申万行业数据链路，让市场、行业和已同步个股正常显示。

风险结果继续定位为辅助决策信息，不表示事件发生概率，不构成投资建议。

## 范围

### 本次实现

- 风险中心市场同步按钮、当前股票同步按钮和同步状态条。
- 后台异步同步、同范围任务互斥、状态查询和部分成功语义。
- 市场、所属行业和当前股票联动同步。
- 暂定分数、暂定等级、结论状态和维度覆盖明细。
- 点击气泡卡片查看每个维度的已使用、缺失、失败和过期指标。
- 当前申万一级行业目录、中文名称和成分映射。
- 当前行业日线风险快照和行业矩阵。
- 趋势默认限制到最近 120 个交易日，避免一次渲染五年明细。

### 不在本次范围

- 用当前行业成分伪造五年历史行业有效期。
- 降低正式评分 80% 门槛。
- 让暂定评估进入滞回、快速升级或风险闸门。
- 全市场 5530 只股票一次性同步。
- 完整的数据运维中心、任务历史审计页面和人工规则治理。
- 伪造免费源无法提供的 ETF 历史真实申赎数据。

## 方案选择

风险中心采用“状态条 + 场景按钮”方案：

- 状态条展示最新数据日期、落后交易日数、同步阶段、进度和错误摘要。
- 市场总览附近提供“同步最新市场数据”。
- 当前股票详情附近提供“同步该股票”，并明确说明将联动市场和所属行业。
- 同步由后台异步执行，页面轮询状态，不阻塞 HTTP 请求。

指标明细采用点击气泡卡片：

- 每个维度右侧展示 `已用数量/指标总数` 和权重覆盖率。
- 点击后展示全部指标状态、分数、来源、可用时间和未参与原因。
- 气泡支持桌面和触屏，不依赖悬浮事件。
- 深度证据仍保留在现有风险证据区域。

## 后端设计

### 同步接口

新增接口：

- `POST /api/risks/sync/market`
- `POST /api/risks/sync/stocks/{symbol}`
- `GET /api/risks/sync/jobs/{jobId}`
- `GET /api/risks/sync/status`

市场同步流程：

1. 确定最近 A 股交易日。
2. 同步市场行情、宽度、跨市场和市场级资金事件。
3. 同步当前申万一级行业目录与成分。
4. 同步全部申万一级行业日线。
5. 计算市场和行业三个周期风险快照。
6. 返回已更新对象数、数据日期、不可用数据集和快照摘要。

股票同步流程：

1. 校验股票属于当前 A 股股票池。
2. 同步市场依赖和该股票当前行业映射。
3. 同步所属行业日线和该股票行情、估值与事件数据。
4. 计算市场、行业和股票三个周期快照。
5. 返回三层对象的更新结果。

后台复用现有 `applicationTaskExecutor`、风险工作流、断点和幂等写入能力。首版任务运行状态保存在进程内，采集结果、检查点和快照继续持久化；服务重启后未完成任务状态可以丢失，但已完成数据不会丢失。相同同步范围只允许一个活动任务，新请求返回现有 `jobId`。

任务状态固定为：

- `queued`
- `running`
- `succeeded`
- `partial_success`
- `failed`

任务阶段至少包括：

- `resolving_trade_date`
- `syncing_market`
- `syncing_industry`
- `syncing_stock`
- `scoring`
- `completed`

### 暂定评估

正式评分保持现有规则：

- 整体覆盖率至少 80%。
- 每个正式维度有效权重至少 60%。
- V、C、A 和 T/S 必备证据满足门控要求。

新增只读展示计算，不覆盖正式快照字段：

- `conclusionStatus`: `formal/provisional/insufficient/unavailable`
- `provisionalScore`
- `provisionalLevel`
- `dimensionCoverage`
- `missingIndicators`
- `dataAsOf`
- `staleTradingDays`

暂定评估资格：

- 整体覆盖率至少 20% 且低于 80%。
- 至少两个维度存在可用或有效零值证据。
- 数据源整体不可用时不形成暂定评估。

暂定维度分采用该维度现有有效指标的权重归一化平均：

`暂定维度分 = Σ(指标分 × 指标权重) / Σ(已用指标权重)`

暂定总分按现有 V/T/S/C/A 维度权重，在已有暂定维度间归一化计算。缺失权重只在“暂定展示计算”中归一化，不改变正式评分、不写入正式总分，也不用于风险闸门。

暂定等级按暂定总分映射：

- `[0, 40)`：`normal`
- `[40, 65)`：`watch`
- `[65, 80)`：`warning`
- `[80, 100]`：`critical`

当 V、C、A 或 T/S 的正式门控信息缺失时，暂定等级最高限制为 `watch`。暂定结果不生成风险阶段，不执行两日确认、快速升级、滞回退出或 easing。

### 指标状态

每个指标返回：

- `code`
- `name`
- `dimension`
- `weight`
- `status`
- `used`
- `score`
- `rawValue`
- `source`
- `observedAt`
- `availableAt`
- `reason`

状态固定为：

- `used`
- `insufficient_history`
- `not_integrated`
- `source_failed`
- `stale`

有有效证据且实际进入暂定或正式计算时为 `used`。指标目录中存在但当前对象没有任何观测记录时为 `not_integrated`；有审计观测时根据质量状态和失败原因映射为更具体的状态。

### 行业数据

优先修复运行环境的可信 CA 证书链，继续保留 TLS 校验。申万历史接口失败时使用当前数据降级：

1. `sw_index_first_info` 获取申万一级行业代码和中文名称。
2. `index_component_sw` 获取当前行业成分。
3. 当前映射保留真实 `observedAt` 和 `availableAt`。
4. 有效日期对齐到请求的最近交易日，但知识可用时间保持真实抓取时间，因此不会进入该交易日收盘时点的正式历史评分。
5. 当前映射允许用于同步完成后的当前对象导航、暂定行业评估和股票联动同步。

通过 Flyway `V3` 为 `risk_object_exposure` 增加 `parent_object_name`，行业中文名称随当前行业映射持久化；查询接口优先返回中文名称。行业日线继续使用 `index_hist_sw`，已有指标用于暂定评估；历史成分不足的事实继续显示在指标明细中。

## 前端设计

### 同步状态条

风险提示下方增加同步状态条：

- 最新风险数据日期。
- 与最近交易日的差值。
- 当前同步阶段和进度。
- “同步最新市场数据”按钮。
- 部分成功或失败的数据集摘要。

同步完成后自动重新加载总览、行业、股票和当前详情。同步失败时保留旧数据，不清空页面。

### 暂定结论

市场、行业矩阵和对象详情统一按 `conclusionStatus` 展示：

- `formal`：正式评估。
- `provisional`：暂定评估，并显示完整度。
- `insufficient`：证据过少。
- `unavailable`：数据源不可用。

正式字段优先；非正式时展示 `provisionalScore` 和 `provisionalLevel`。所有暂定结果都带明显标签，不与正式等级混淆。

### 维度指标气泡

V/T/S/C/A 每行显示：

- 暂定或正式维度分。
- 进度条。
- `2/6 可用`。
- 指标权重覆盖率。

点击可用数量打开气泡，按指标目录顺序展示指标状态。已使用指标展示分数、来源和可用时间；未使用指标展示具体原因。

### 行业矩阵

行业矩阵至少显示：

- 申万一级行业中文名称和代码。
- 暂定或正式分数。
- 结论状态和完整度。
- 最新数据日期。

点击行业后继续使用现有三级下钻加载行业详情和当前行业股票。

## 错误处理

- 单个非核心源失败：任务为 `partial_success`，保存并展示已经成功的数据。
- 核心市场行情失败：市场任务为 `failed`，保留旧快照。
- 行业历史源失败但当前目录和成分成功：任务为 `partial_success`，行业显示暂定评估。
- 当前行业目录和成分均失败：行业阶段失败，市场结果仍可成功。
- 个股源失败：市场和行业可成功，股票结果保留旧值并展示失败原因。
- 所有错误只返回经过截断和清理的摘要，不向前端暴露敏感配置或完整堆栈。

## 验收与测试

### 后端

- 市场同步和股票联动同步范围测试。
- 同范围任务互斥、任务状态迁移和部分成功测试。
- 暂定分数、20% 下限、两维度要求和等级上限测试。
- 正式评分与影子闸门不受暂定结果影响。
- 当前行业映射保留真实可用时间，不进入过去时点正式评分。
- 行业名称、当前成分和行业快照查询测试。
- 同步重复执行幂等。

### 前端

- 状态条、轮询、完成刷新和失败保留旧数据。
- 市场、行业和股票的正式、暂定、证据过少和不可用状态。
- 指标气泡的全部状态与详情。
- 行业矩阵中文名称和暂定结果。
- 趋势默认最近 120 个交易日。
- typecheck、相关 Vitest、lint 和构建验证。

### 集成验收

在 Docker Desktop、MySQL、AKTools 和风险数据网关运行时：

1. 市场同步后风险中心日期达到最近交易日。
2. 市场显示暂定或正式结论，而非笼统“数据不足”。
3. 行业矩阵至少展示当前全部申万一级行业。
4. 选择一只股票同步后，市场、所属行业和股票均有最新快照。
5. 每个维度能看到实际使用和缺失的指标。
6. 数据源部分失败时已有结果仍然可见。
