# 本地登录页移除滑块验证设计

## 背景与目标

当前 `web-antd` 登录页在用户名和密码之外强制要求完成前端滑块验证，阻碍风险中心的自动化页面排查。后端登录接口只接收用户名和密码，滑块结果不会发送到后端，因此移除该前端字段不会改变后端认证协议。

本次目标是让当前使用的 `web-antd` 应用可以直接通过用户名和密码登录，同时保持现有账号认证、访问令牌和权限加载流程不变。

## 方案

仅修改 `apps/web-antd/src/views/_core/authentication/login.vue`：

- 移除 `SliderCaptcha` 和不再需要的 `markRaw` 导入。
- 从登录表单 Schema 中移除 `captcha` 字段及其必填校验。
- 保留账号选择、用户名、密码、登录 API 和认证 Store 的现有行为。

不修改共享验证码组件，不修改 `web-naive`、`web-ele`、`web-antdv-next` 和 `web-tdesign` 示例应用，也不修改后端登录接口。

## 数据流

登录表单提交后仍只通过现有 `authStore.authLogin` 调用 `/auth/login`，成功后继续获取用户信息和权限码并跳转首页。此次变更只移除提交前的前端滑块阻断，不绕过用户名和密码认证。

## 错误处理与安全边界

- 用户名或密码为空时，继续由现有表单校验阻止提交。
- 用户名或密码错误时，继续显示后端认证错误。
- 不引入自动登录、固定令牌或后端认证绕过。
- 该调整只覆盖当前 `web-antd` 应用。

## 测试与验收

- 先增加一个失败测试，验证登录页不再引用或注册 `SliderCaptcha`/`captcha` 字段。
- 修改后运行该定向测试。
- 运行前端类型检查或相关 `pnpm check` 验证。
- 使用浏览器确认登录页不再出现滑块，并能够凭现有账号登录后进入风险中心。
