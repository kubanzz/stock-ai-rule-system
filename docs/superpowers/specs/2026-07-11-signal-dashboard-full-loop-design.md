# 信号看板前后端完整闭环设计

## 1. 目标

在现有 Vue 3 + Vben Admin + Ant Design Vue 和 Spring Boot + MyBatis-Plus 架构内，将信号看板升级为可连续操作的股票辅助决策工作台，并消除当前“页面可操作但后端未真实生效”的断点。

交付后的看板应满足：

- 股票池可创建、重命名、删除，池内股票可添加、移除和分组，刷新后数据仍然存在。
- 市场、股票池、交易日、股票、信号、行业和置信度筛选均由后端真实执行。
- 指标卡、表格总数和市场环境使用同一筛选口径，不出现前端二次筛选造成的统计不一致。
- 大盘趋势使用真实行情折线图；行业强弱使用横向条形图。
- 所有信号保持辅助决策定位和风险提示，不输出确定性预测或收益保证。

## 2. 方案选择

### 2.1 候选方案

1. 仅重排现有页面：改动最小，但股票池不持久化、筛选参数未生效、市场数据固定等问题仍然存在。
2. 独立大屏式重构：视觉表现强，但偏离 Vben 控制台的高频操作方式，移动端和表格交互成本较高。
3. 工作台式看板并补齐真实数据闭环：沿用现有控制台骨架，补后端领域模型和聚合查询，兼顾实现风险、数据真实性与操作效率。

采用方案 3。

## 3. 范围

### 3.1 本次实现

- 自定义股票池及股票池成员持久化。
- 股票池管理抽屉和添加股票抽屉。
- 看板服务端筛选、排序和分页。
- 基于 `stock_daily_quote` 的价格、涨跌幅、大盘趋势和行业强弱。
- 基于 `stock_signal_daily` 的信号统计、7 日信号情绪和高风险概览。
- 基于 `stock_actual_result.hit_5d` 的 5 日命中率；无验证数据时明确显示暂无数据。
- 看板响应式布局、加载状态、空状态、错误反馈和数据更新时间。
- 从看板进入股票详情时保留交易日上下文。

### 3.2 本次不实现

- 新闻采集、新闻情绪模型和政策事件数据源。
- 多租户或按登录用户隔离股票池。
- 实时行情推送、WebSocket 和分钟级 K 线。
- 批量文件导入股票池。

原型中的“新闻情绪”在正式实现中改为“信号情绪（7 日）”，“政策与事件风险”改为“风险概览”。原因是当前系统没有新闻和政策事件数据源，不使用固定值伪装真实数据。

## 4. 数据模型

### 4.1 `stock_watchlist`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 |
| `pool_code` | `VARCHAR(64)` | 稳定业务编码，唯一 |
| `pool_name` | `VARCHAR(128)` | 股票池名称 |
| `market` | `VARCHAR(32)` | `A股`、`港股`、`美股` |
| `sort_order` | `INT` | 展示顺序 |
| `is_system` | `TINYINT(1)` | 系统池不可删除 |
| `created_at` | `DATETIME` | 创建时间 |
| `updated_at` | `DATETIME` | 更新时间 |

系统初始化一个 `my-follow` 股票池。全量股票不落为股票池成员，由查询接口以 `all` 虚拟池返回。

### 4.2 `stock_watchlist_item`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 |
| `watchlist_id` | `BIGINT` | 股票池主键 |
| `symbol` | `VARCHAR(32)` | 股票代码 |
| `group_name` | `VARCHAR(64)` | 可选分组 |
| `sort_order` | `INT` | 池内排序 |
| `created_at` | `DATETIME` | 创建时间 |
| `updated_at` | `DATETIME` | 更新时间 |

唯一键为 `watchlist_id + symbol`。添加重复股票返回业务错误，不静默覆盖。删除股票池时级联删除成员；系统池禁止删除。

## 5. 后端设计

### 5.1 分层

- `StockWatchlist`、`StockWatchlistItem`：MyBatis-Plus 实体。
- 对应 Mapper：负责基础持久化。
- `StockWatchlistService`：负责股票池 CRUD、成员增删和业务校验。
- `StockDashboardQueryService`：负责服务端筛选、分页、指标与市场环境聚合。
- `StockConsoleController`：维持 `/api` 下 REST 风格入口和统一 `AjaxResult` 返回。

现有 `StockConsoleQueryServiceImpl` 继续承载其他控制台页面；信号看板相关逻辑委托给上述两个边界清晰的服务，避免聚合类继续膨胀。

### 5.2 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/signals/dashboard` | 看板查询，支持全部筛选、排序和分页 |
| `GET` | `/api/watchlists?market=` | 查询股票池摘要与成员 |
| `POST` | `/api/watchlists` | 创建股票池 |
| `PUT` | `/api/watchlists/{poolCode}` | 重命名或调整市场 |
| `DELETE` | `/api/watchlists/{poolCode}` | 删除自定义股票池 |
| `POST` | `/api/watchlists/{poolCode}/stocks` | 添加股票 |
| `DELETE` | `/api/watchlists/{poolCode}/stocks/{symbol}` | 移除股票 |

`GET /api/signals/dashboard` 参数：

- `date`、`market`、`poolCode`
- `symbol`、`signal`、`industry`
- `confidenceMin`、`confidenceMax`
- `pageNum`、`pageSize`
- `sortField`、`sortOrder`

响应保留 `tradeDate`、`riskDisclaimer`、`metrics`、`signals`、`marketContext`，并补充 `pageNum`、`pageSize`、`total`、`availableIndustries` 和 `dataUpdatedAt`。

### 5.3 查询口径

1. 交易日为空时解析当前市场最近一个有信号的交易日。
2. 先按市场和股票池得到候选股票代码集合。
3. 对信号、股票基础信息和当日行情做关联查询，应用其余筛选、排序和分页。
4. 指标卡基于分页前的完整筛选结果统计。
5. 价格与涨跌幅来自选定交易日的 `stock_daily_quote`，无行情时返回 `null`。
6. 5 日命中率只统计 `stock_actual_result.hit_5d` 非空样本，不再使用平均置信度代替命中率。

### 5.4 市场环境

- 大盘走势：通过配置项为市场映射基准代码，默认 `A股 -> 000300.SH`；查询截至选定交易日最近 20 个交易日收盘价。
- 基准行情不存在时返回 `available=false` 和空序列，前端显示“暂无基准行情”，不返回固定模拟走势。
- 行业强弱：按选定市场、交易日对行业股票的 `change_pct` 求平均，返回涨幅前 3 与跌幅后 2。
- 信号情绪：对最近 7 个有效交易日的看涨、看跌、观望、高风险分布计算 0-100 指数，并返回“偏多、均衡、偏空”等辅助标签。
- 风险概览：返回高风险信号数量、占比和最近数据同步状态。

## 6. 前端设计

### 6.1 页面结构

1. 标题与风险提示。
2. 六个指标卡：关注股票、产生信号、看涨、看跌、观望、高风险；命中率在有验证样本时作为补充信息展示。
3. 主工具栏：股票池、市场、交易日、管理股票池、添加股票、刷新、导出。
4. 表格筛选栏：股票搜索、信号、行业、置信度。
5. 服务端分页表格：股票、价格/涨跌幅、系统信号、三类评分、置信度、规则数、周期、更新时间、操作。
6. 市场环境侧栏：20 日大盘折线、行业强弱条形图、7 日信号情绪、风险概览。

### 6.2 组件边界

- `signal-metric-grid.vue`：指标卡。
- `signal-dashboard-toolbar.vue`：主筛选与动作。
- `signal-table.vue`：筛选、表格、分页和详情跳转。
- `market-context-panel.vue`：ECharts 折线、行业排行、情绪与风险。
- `watchlist-manager-drawer.vue`：股票池创建、重命名、删除和成员管理。
- `stock-picker-drawer.vue`：按市场搜索股票、批量勾选并加入指定池，可填写分组。

页面 `index.vue` 只协调查询条件、请求状态和组件事件。

### 6.3 交互

- 市场变化时刷新股票池、行业选项和看板；若当前股票池不属于新市场，回退到该市场第一个可用池。
- 查询条件变更后页码回到 1；表格排序和分页均重新请求后端。
- 新建、重命名、删除、添加和移除成功后刷新股票池与看板统计。
- 删除股票池和移除股票需要二次确认。
- 导出使用当前完整筛选条件导出 CSV；若本次不新增服务端导出接口，前端按服务端最大允许条数重新查询后生成。
- 桌面端为主表 + 侧栏；小屏按工具栏、指标、表格、市场环境顺序堆叠，表格允许横向滚动并固定股票与操作列。

## 7. 错误、空状态与风险约束

- 所有写操作使用 Ant Design 消息反馈；失败时保留抽屉内容，允许用户重试。
- 无信号时保留筛选和指标区域，表格显示对应交易日暂无信号。
- 无行情时价格显示 `--`，大盘折线显示明确空状态。
- 不将置信度描述为成功概率，不将信号写成买入或卖出指令。
- 风险提示固定显示在首屏，不因空数据或请求失败消失。

- 分页总数与指标统计使用分页前结果。
- 价格、涨跌幅和 5 日命中率口径正确。
- 基准行情缺失时不返回固定数据。
- Controller 参数绑定和统一返回结构测试。

### 8.2 前端

- API 类型与路径契约测试。
- 条件变化重置页码，分页和排序发送正确参数。
- 股票池写操作成功后刷新数据，失败时保留表单。
- 市场环境折线、空状态和响应式布局测试。
- 风险提示始终存在，页面不出现确定性投资文案。
