# 免费公开数据风险衍生网关与五年回填设计

## 1. 背景与目标

当前风险模块已经具备数据库契约、风险 Provider、评分引擎、五年回填命令和覆盖门控，但 AKTools 原生接口不能直接返回风险 Provider 所需的完整规范化历史。部分接口只有当前快照或近期数据，直接反填历史会引入未来函数和幸存者偏差。

本设计采用“免费公开数据 + 可审计代理指标”完成第一阶段闭环：新增轻量衍生网关，规范化 AKTools 原始数据，计算可复现的历史指标并显式标记数据质量。正式评分仍要求 26 项指标实际加权覆盖至少 80%，缺失权重不重分配。

目标：

- 为 A 股市场、申万一级行业及具备有效行业映射的股票提供五年正式风险快照所需历史输入；
- 使用额外六年上下文支撑五年滚动分位基线；
- 让 V1、V3、V4、V5、T1—T4、S1、S2、S4、C1—C5、A1、A3—A5 共 20 项进入正式覆盖，理论总覆盖为 81%；
- 将来源、抓取时间、观测时间、可用时间、计算公式和质量状态完整保留下来；
- 支持样本先行、断点续跑、缓存复用和失败后安全重试。

非目标：

- 不把风险分描述为暴跌概率；
- 不购买或接入商业数据源；
- 不伪造 ETF 真实申赎、历史行业退出、逐档盘口或基金真实仓位；
- 不实现 V2、V6、S3、S5、C6；
- 不放宽现有覆盖率、证据门控或影子闸门限制。

## 2. 方案选择

### 2.1 采用方案：独立 Python 衍生网关

在 `infra/risk-data-gateway` 新增独立 Docker 服务，默认监听 `127.0.0.1:18090`。网关调用现有 AKTools 服务，负责历史采集编排、缓存、交易日对齐、指标衍生、分页和质量元数据；Java 风险 Provider 继续负责领域对象转换、评分输入和正式持久化。

选择该方案的原因：

- 与现有 `RISK_WARNING_DERIVED_GATEWAY_BASE_URL` 和六个 HTTP 契约一致；
- pandas/Parquet 更适合批量时间序列对齐和横截面宽度计算；
- 数据采集故障不会侵入 Spring Boot 主服务；
- 网关缓存可以删除并重建，MySQL 仍是唯一业务权威数据源。

### 2.2 未采用方案

- 全部内嵌 Java：容器更少，但会把高成本历史采集、分析缓存与在线业务服务耦合，增加超时和内存风险。
- 直接放宽回填门槛：修改量最小，但会允许不完整快照或代理事实进入正式评分，不满足审计要求。

## 3. 总体架构

```text
AKTools :8090
    |
    v
risk-data-gateway :18090
    |-- AKTools HTTP 客户端
    |-- 交易日/代码/行业目录
    |-- 原始 Parquet 分区缓存
    |-- 历史对齐与衍生计算
    `-- 质量、血缘与分页元数据
    |
    v
Spring Boot Risk Provider
    |-- point-in-time 校验
    |-- 覆盖率门控
    |-- 风险评分与影子闸门
    v
MySQL 风险观测、证据、快照与 checkpoint
```

边界规定：

- AKTools 只提供公开原始数据；
- 衍生网关不计算 V/T/S/C/A 维度分、总分或风险等级；
- Java Provider 不猜测历史边界，只按网关的时间与质量元数据决定是否纳入评分；
- 网关缓存不是业务备份，删除后可由来源重建；
- MySQL 中的规范化记录和回填报告是业务审计依据。

## 4. 网关接口与组件

### 4.1 HTTP 接口

网关提供：

- `GET /health`：返回服务版本、AKTools 连通性和缓存状态；
- `GET /api/risk/market-daily`：目标、基准、龙头的对齐日线；
- `GET /api/risk/valuation`：PE TTM、盈利收益率、无风险收益率和风险溢价原始分量；
- `GET /api/risk/breadth`：上涨、下跌、新高、新低和均线上方家数；
- `GET /api/risk/cross-market`：领先资产收益、对齐交易时间和独立市场序列；
- `GET /api/risk/sw1-membership`：有来源依据的申万一级行业有效区间；
- `GET /api/risk/etf-redemption`：免费源无法提供真实历史申赎时返回明确的历史不足响应。

所有数据接口接受现有契约中的 `start_date`、`end_date`、`objects` 和可选 `cursor`。响应包含记录数组及 `meta`：

- `historyComplete`；
- `insufficientHistory`；
- `earliestAvailableDate`；
- `historyGapReason`；
- `nextCursor`；
- `source`、`sourceVersion`；
- `calculationVersion`；
- `fetchedAt`。

数据记录继续使用 Java Provider 已约定的 camelCase 字段，并至少包含 `objectType`、`objectId`、`tradeDate`、`observedAt`、`availableAt` 和具体原始分量。

### 4.2 内部组件

- `AkToolsClient`：连接池、超时、限速、指数退避和字段校验；
- `TradingCalendar`：统一 A 股开市日和跨市场日期对齐；
- `RawCache`：读取、原子写入和校验 Parquet 分区；
- `DatasetBuilders`：分别构建行情、估值、宽度、跨市场和行业数据；
- `AvailabilityPolicy`：生成保守的 point-in-time 可用时间并记录策略版本；
- `CoverageMetadata`：汇总历史起点、缺口和完整性；
- `ApiModels`：稳定输出 Java Provider 已有契约。

组件之间仅通过类型化数据表和元数据对象通信，避免在 API 路由中混合抓取与计算逻辑。

## 5. 数据范围与评分资格

### 5.1 正式数据

以下指标在全部必需分量齐全且历史窗口完整时可进入正式评分：

| 维度 | 指标 | 免费数据处理方式 |
|---|---|---|
| V | V1 | 个股/行业 PE 与同期无风险收益率计算风险溢价 |
| V | V3 | 目标相对基准的历史超额收益 |
| V | V4 | 成交量、换手和价格序列形成明确标注的交易拥挤代理 |
| V | V5 | 融资余额水平及历史分位 |
| T | T1—T4 | 业绩预告和公告按受控经济含义字典转换；无事件可为有效零值 |
| S | S1、S2、S4 | 全球资产与 A 股交易日、时区对齐后的收益和滚动相关性 |
| C | C1—C5 | 龙头、宽度、量能、相对强弱、趋势和缺口原始分量 |
| A | A1 | 融资余额实际下降代理 |
| A | A3 | 趋势距离与实现波动率比值代理 |
| A | A4 | 宽度构成的日频市场深度代理，明确不是盘口深度 |
| A | A5 | 目标与基准收益的滚动相关系数 |

代理指标必须在 `attributes` 中包含 `proxy=true`、公式、窗口和输入字段。只要公式、输入或窗口不完整，记录即为 `insufficient_history`，不允许填零。

### 5.2 补充审计数据

近期解禁、近期减持、当前 ETF 订单流等真实但历史不完整的数据可以保存为审计或 UI 补充证据，但质量固定为 `insufficient_history`，不推进 checkpoint，不参与正式覆盖和风险评分。

### 5.3 明确缺失数据

- V2、V6、S3、S5、C6 不生成记录；
- A2 在没有真实 ETF 申赎份额/净额历史时返回 `historyComplete=false`，不得用净值、成交额或申赎状态替代；
- 缺失权重不重分配，因此理论正式覆盖上限为 81%；
- 实际覆盖低于 80% 或任一维度证据门槛不足时，不生成正式等级与闸门建议。

## 6. 时间语义与防未来函数

每条记录区分：

- `tradeDate`：指标归属交易日；
- `observedAt`：原始事实发生或市场收盘时间；
- `availableAt`：该事实最早可被当时系统安全使用的时间；
- `fetchedAt`：本次实际抓取时间。

可用时间策略：

- A 股日线及由其形成的宽度：当日收盘后保守可用；
- 当日估值：来源没有精确发布时间时，从下一 A 股交易日开始可用；
- 公告与业绩预告：优先真实披露时间，只有日期时从下一交易日开始可用；
- 全球市场：按原市场实际收盘时间转换为北京时间，不提前归入 A 股交易日；
- 融资融券：按来源披露频率延迟到下一交易日使用；
- 行业成分：只从明确计入日期或实际抓取日开始有效，不推断历史退出时间。

响应同时携带 `availabilityPolicyVersion`。无法确定 `availableAt` 的记录标记为历史不足。对同一历史事实出现修订但没有可靠版本顺序时，拒绝该批次，不依据返回顺序任选一个值。

## 7. 缓存和性能

网关使用挂载卷中的 Parquet 分区缓存：

```text
cache/<dataset>/<object>/<year>/part-<content-hash>.parquet
cache/manifests/<dataset>/<request-hash>.json
```

清单记录来源函数、规范化参数、来源版本、覆盖日期、行数、内容哈希、抓取时间和质量摘要。写入先落临时文件，校验成功后原子替换；内容哈希相同的重跑不产生新分区。

执行策略：

- 请求区间已被有效缓存覆盖时不访问 AKTools；
- 只补齐缺失日期，不整段重抓；
- 全市场日线按受控并发抓取，遇到限频自动降低并发；
- 市场宽度按交易日聚合一次，为所有对象复用；
- 三个风险周期共享同一原始序列，不重复扫描；
- API 通过稳定 cursor 分页，单页大小受配置限制。

默认采集区间为评分结束日前十一年：后五年生成目标快照，前六年提供滚动基线与最长上下文。若某对象上市时间不足，则保留真实最早日期并报告历史不足，不补造记录。

## 8. 行业与对象处理

- 市场对象固定为 `market:CN-A`；
- 行业对象使用申万一级指数自身历史行情和估值，不依赖当前成分反算历史指数；
- 当前成分带明确计入日期时，可形成 `[validFrom, 当前]` 的暴露；
- 缺少调出历史时，不生成已经退出股票的历史暴露，也不将当前行业映射反填到计入日期之前；
- 个股某日没有有效行业暴露时，可以保存市场层和个股特有层观测，但不得生成需要完整三层合成的正式个股快照；
- 风险中心对此显示“行业历史映射不足”，而不是 `normal`。

## 9. 错误处理与质量状态

- 上游调用失败、超时、字段结构变化：HTTP 失败并由 Java 端记为 `unavailable`；
- 请求成功但免费源客观不覆盖所需历史：HTTP 200，`historyComplete=false`、`insufficientHistory=true` 并给出原因；
- 事件查询成功且完整范围内没有事件：`valid_zero`；
- 市场、估值、行业或宽度空集合：历史不足，不得视为零；
- 缓存损坏：隔离损坏分区并重新拉取，不向下游返回部分成功；
- 单个对象失败：记录对象级失败并继续当前批次，最终覆盖门控决定整批是否可进入评分；
- 所有异常仅保留脱敏摘要，不在报告中输出 URL 凭据或环境变量值。

网关 `/health` 仅代表进程、缓存和 AKTools 连通，不代表历史覆盖通过；历史覆盖只能由具体数据响应和 Java 回填报告证明。

## 10. 回填流程

1. 预检 MySQL/Flyway、交易日历、股票池、AKTools、衍生网关和缓存卷；
2. 下载并缓存公共序列：指数、无风险收益率、融资和全球市场；
3. 获取全 A 股历史日线并一次性构建历史宽度；
4. 运行固定 50 只样本，生成数据集、指标、维度和周期覆盖报告；
5. 样本必须满足 80% 总覆盖、维度证据门槛、三个周期正式市场快照和时间一致性；
6. 样本通过后按 200 只一批扩展全市场；
7. 失败批次保留 checkpoint 和缓存，修复后从断点继续；
8. 全量完成后执行数据库审计和风险中心 API/UI 冒烟。

样本未通过时停止，不进入全市场；不得通过修改报告、直接改表或把历史不足改为有效零值绕过门控。

## 11. 测试与验收

### 11.1 网关测试

- AKTools 固定响应契约及字段漂移；
- 分页、cursor 稳定性和请求参数规范化；
- Parquet 缓存命中、增量补齐、原子写入及损坏恢复；
- A 股/全球交易日和时区对齐；
- `observedAt <= availableAt <= asOf`；
- 历史宽度、收益率、相关性、趋势、缺口和风险溢价公式；
- 空数据、限频、超时和历史不足的状态区分；
- ETF 接口不得把净值或订单流输出为真实申赎。

### 11.2 Java 集成测试

- 六个网关端点与现有 DTO 契约一致；
- 20 项支持指标在输入完整时计入覆盖，六项缺失指标不重分配权重；
- 81% 理论覆盖和 80% 实际门槛边界；
- 行业暴露有效期和无暴露个股的数据不足结果；
- 回填幂等、断点续跑及不可用数据不推进 checkpoint；
- 影子闸门始终 `enforced=false`。

### 11.3 真实验收

- Docker 中 AKTools 与网关均健康；
- 运行固定 50 只样本，退出码为 0；
- 报告中实际覆盖至少 80%，不可用数据集数量为 0；
- 三个周期都有正式市场快照；
- MySQL 风险观测、证据、快照和闸门记录非空且幂等重跑数量稳定；
- 抽样核对至少一个市场、一个行业和一个股票对象的计算输入与来源；
- 风险中心能展示真实数据、数据不足原因、原始/建议置信度和影子闸门状态。

样本完成并验收前，不宣称五年数据已经完成导入；样本失败时只报告真实失败项和已缓存范围。

## 12. 部署与回滚

- 在 `docker-compose.market-data.yml` 中新增 `risk-data-gateway`，只绑定本机 `18090`；
- 网关使用固定 Python 与依赖版本，AKTools 地址、缓存目录、并发、超时和重试由环境变量配置；
- 不保存密钥、Token 或数据库密码；网关不直接连接业务 MySQL；
- 停止或删除网关不会影响已有正式风险数据；
- 回滚代码时保留 MySQL 数据和回填报告，缓存卷可保留供审计或安全删除后重建；
- 正式导入前继续使用现有数据库备份和确认令牌机制。

## 13. 变更边界

预计变更集中在：

- 新增 `infra/risk-data-gateway`；
- 扩展 `docker-compose.market-data.yml`；
- 增加网关单元测试与真实冒烟脚本；
- 对现有 Java 网关契约做最小必要兼容修正；
- 更新五年回填运行手册和覆盖报告说明。

不修改风险公式、数据库 DDL、前端页面结构、信号方向、正式闸门策略或已有 API 路由。
