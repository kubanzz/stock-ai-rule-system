# 行业风险适用指标与分阶段同步设计

## 背景

风险中心已经切换为读取 `risk_score_snapshot` 和 `risk_score_evidence`，页面加载速度得到改善，但当前 31 个申万一级行业仍全部显示“数据不足”。现有 `risk-warning-v1` 对市场、行业和个股统一使用 500 权重的完整指标目录作为完整度分母，而行业数据源只能够稳定提供申万日线派生指标，并从市场继承外部传导指标。因此，行业即使把当前可获得数据全部采齐，仍无法达到统一的 80% 正式结论门槛。

此外，市场手工同步虽然会采集并保存行业日线观测，但评分读取的 SQL 范围只包含原始计划中的 `market:CN-A`，没有把采集阶段动态扩展出的行业对象纳入观测读取范围。结果是行业评分仍然只能看到从市场继承的 S1、S2、S4，形成 14% 的旧式完整度。

风险评分继续作为辅助决策信息，不代表事件发生概率，不构成投资建议。

## 目标

1. 为市场、行业和个股定义各自的适用指标集合，完整度只在该对象类型的适用集合内计算。
2. 保留整体 80% 和核心维度 60% 的质量门槛，不把缺失数据当成零风险，也不简单降低全局门槛。
3. 修复市场同步评分读取范围，使已经保存的行业日线观测真正进入行业评分。
4. API 和页面明确区分“不适用”与“数据缺失”，不再把行业无法提供的指标显示为异常缺失。
5. 市场手工同步先生成可用的行业快照，再执行耗时的市场宽度采集；慢任务不再阻塞行业最新评分发布。
6. 提供显式、仅使用已落库数据的最近两年行业评分重建能力，不在应用启动时自动执行大规模回填。

## 方案决策

采用“对象类型覆盖配置”方案，不采用以下方案：

- 不把全局正式门槛从 80% 降到 40%，避免残缺的市场和个股数据被误判为正式结论。
- 不把缺失指标填零，缺失不等于低风险。
- 本次不等待所有行业专属数据源接入后再发布；未来新增数据源时，可以显式扩充行业适用指标集合并升级模型版本。

## 模型版本与兼容性

新增 `risk-warning-v2` 评分语义，并将默认模型版本从 `risk-warning-v1` 调整为 `risk-warning-v2`。数据库唯一键已经包含 `model_version`，因此 v1 与 v2 快照可以并存，不需要数据库迁移。

覆盖配置必须同时接收对象类型和模型版本：

- `risk-warning-v1` 以及未知旧版本继续使用完整 500 权重目录，历史快照的 14% 不被查询层重新解释。
- `risk-warning-v2` 的市场和个股继续使用完整目录。
- `risk-warning-v2` 的行业使用行业适用指标目录。

查询层根据快照自身的 `model_version` 选择覆盖配置，避免把 v1 证据按 v2 分母重新计算。

## 行业适用指标目录

`risk-warning-v2` 行业目录以当前可稳定生成的行业观测为准：

| 维度 | 适用指标 | 适用权重 |
|---|---|---:|
| V 结构脆弱 | V3、V4 | 35 |
| T 实质触发 | 无 | 0 |
| S 外部传导 | S1、S2、S4 | 70 |
| C 本地确认 | C1、C3、C4、C5 | 65 |
| A 强制卖出 | A3、A5 | 35 |
| 合计 | 11 个指标 | 205 |

行业整体完整度计算为：

```text
行业有效适用指标权重 / 205
```

各维度覆盖率计算为：

```text
该维度有效适用指标权重 / 该维度适用指标总权重
```

正式结论仍要求：

- 整体适用指标完整度至少 80%；
- 行业适用的 V、C、A 各自至少覆盖 60%；
- T 与 S 中至少一个适用维度覆盖 60%。行业 T 当前不适用，因此必须由 S 满足该门槛；
- 必须存在真实的 V、C、A、S 证据；
- 质量为 `unavailable`、`stale` 或 `insufficient_history` 的证据不计入有效权重。

当全部 11 个行业适用指标有效时，完整度为 100%，而不是旧口径下的 41%。

## 组件边界

### 对象类型覆盖目录

新增一个引擎层覆盖目录，职责仅包括：

- 按 `modelVersion + RiskObjectType` 返回适用指标定义；
- 返回各维度适用定义、总适用权重和维度适用权重；
- 判断某个指标或维度是否适用。

评分引擎和查询解释器必须共享这个目录，禁止分别维护两份行业指标清单。

### 评分引擎

`RiskScoringEngine` 使用覆盖目录替代固定的 `500` 和固定的维度分母 `100`：

- 非适用证据不参与分数和完整度；
- 缺失原因只针对适用指标生成；
- 不适用维度不触发“维度不足”错误；
- 核心维度和 T/S 组合门槛仍按适用维度执行。

### 查询解释器

`ProvisionalRiskAssessmentCalculator` 接收对象类型和模型版本，并使用同一覆盖目录计算证据完整度、维度覆盖率和指标状态。

API 的维度结构增加 `applicable` 字段：

- 行业 T 返回 `applicable=false`；
- 部分适用维度的 `usedCount/totalCount` 只统计适用指标；
- 仍返回完整指标目录用于解释，但非适用指标状态为 `not_applicable`，原因显示“当前对象类型不适用该指标”；
- v1 快照继续按旧目录展示，保持历史语义。

### 前端展示

前端新增 `not_applicable` 状态：

- 完全不适用的维度显示“不适用”，不显示“数据不足”；
- 指标弹层使用灰色“不适用”标签；
- 适用维度显示“已使用数 / 适用指标数”，例如 V 显示 `2/2`，而不是 `2/6`；
- 只有适用但未获得有效证据的指标才显示“尚未接入”“历史不足”“源失败”或“已过期”。

## 修复行业观测评分范围

市场手工同步的计划对象是 `market:CN-A`，采集阶段会根据行业暴露关系把 31 个申万一级行业动态加入 `MARKET_DAILY` 任务。评分查询范围也必须在请求包含 `market:CN-A` 时加入全部行业对象，否则已经保存的 `sw_daily` 观测不会被加载。

`JdbcRiskWorkflowRepository` 的对象范围规则调整为：

- 请求包含个股时：读取请求个股、市场和全部候选行业，保持现有层级评分语义；
- 请求包含 `market:CN-A` 时：读取市场和全部行业；
- 仅请求明确行业时：只读取明确行业；
- 所有查询继续按日期、`asOf` 和模型版本过滤。

## 分阶段市场同步

市场手工同步拆成两个顺序阶段：

### 阶段一：行业快速评分

依次执行：

1. 申万行业成员关系；
2. 市场与申万行业日线；
3. 跨市场数据，用于生成并向行业继承 S1、S2、S4；
4. 使用已落库数据生成当日市场和行业 v2 快照。

阶段一完成后页面即可读到当日行业快照，不等待市场宽度任务。

### 阶段二：慢数据补算

继续执行估值、市场宽度、融资与 ETF 资金流等慢数据任务，完成后再次从已落库数据评分，并按相同 v2 唯一键更新当日快照。

阶段二失败或超时不得删除阶段一快照；同步任务可以报告部分成功。两个阶段的计数汇总到原有同步结果，不改变现有 API 的单活动任务约束。

日常全市场收盘任务暂不拆分，以避免扩大本次改动范围；本次先解决风险中心手工市场同步和行业展示问题。

## 最近两年行业评分重建

新增显式的“行业 v2 重建”入口，只调用 `RiskWarningWorkflow.scoreStoredData`：

- HTTP 入口为 `POST /api/risks/sync/sectors/rebuild`，返回现有 `RiskSyncJob` 结构；
- 结束日为最近交易日；
- 评分区间为结束日前两年至结束日；
- 对象范围为市场和全部有效申万一级行业；
- 不重新调用 TuShare、AKTools 等外部数据源；
- 不删除 v1 快照，以新的 `risk-warning-v2` 行保存结果；
- 复用现有单活动同步任务互斥，避免与市场同步同时运行；
- 任务范围标识为 `sector:SW1:rebuild`，现有 `GET /api/risks/sync/jobs/{jobId}` 可查询结果；
- 默认不在启动时自动运行，必须显式触发。

如果已落库行业观测本身不足，重建结果仍保持 `insufficient`，不得伪造正式评分。

## 错误处理与安全边界

- 覆盖配置为空或适用总权重为零时直接拒绝评分，不能除零或返回 100%。
- 行业某个适用维度没有证据时，该维度分数为空并产生明确缺失原因。
- v2 之外的旧模型版本保持旧口径，避免历史结果被无声修改。
- 阶段二失败保留阶段一快照，并将任务状态标记为部分成功或失败原因。
- 两年重建与正常同步互斥，不自动并发写同一快照。
- 不修改原始观测和冷归档数据，不执行自动删除。

## 测试策略

### 后端单元测试

- 行业 11 个适用指标全部有效时，完整度为 1.0000 并能生成正式结论。
- 行业缺少适用指标时按 205 分母扣减；不适用指标不影响完整度。
- 行业 V、C、A、S 门槛按各自适用权重计算，T 不适用时由 S 满足组合门槛。
- v1 行业仍按 500 分母计算，保持历史兼容。
- 查询解释器对 v2 行业返回适用计数、`applicable=false` 和 `not_applicable`；v1 展示不变。
- 市场范围读取包含行业观测；明确行业范围不扩大到其他行业。
- 手工市场同步先执行快速阶段并保存快照，再执行慢阶段并二次评分。
- 慢阶段失败时快速阶段快照仍保留并返回可审计状态。
- 两年重建只读已落库数据，不调用 Provider。

### 前端测试

- 不适用维度显示“不适用”。
- `not_applicable` 指标显示对应标签和原因。
- 适用指标计数不包含非适用指标。
- 现有正式、暂定、不足和不可用状态展示不回归。

## 验收标准

1. 新生成的 `risk-warning-v2` 行业快照以 205 适用权重为分母，全部适用证据有效时完整度为 100%。
2. 行业 T 维度显示“不适用”，V/C/A/S 只统计行业适用指标。
3. 市场同步保存的 `sw_daily` 行业观测能被评分读取，不再只剩市场继承的 S 证据。
4. 行业快速阶段完成后，当日行业快照已经可查询；市场宽度仍运行时不回退到旧日期。
5. 最近两年行业 v2 重建可以显式执行，并且不调用外部数据源、不覆盖 v1 行。
6. 市场和个股的完整度、正式门槛和历史 v1 语义保持不变。
7. 后端定向测试、后端完整测试、前端风险中心测试和静态检查通过。

## 非目标

- 本次不新增行业 V1、V5、A1、A4 或 T 类数据源。
- 本次不改变风险等级分段、状态机和闸门阈值。
- 本次不删除旧 v1 快照或原始观测数据。
- 本次不自动启动两年重建，也不在应用启动时执行外部全量采集。
